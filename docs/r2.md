# Stockage Cloudflare R2

Les photos (`annonces/`, `visuels/`) et le catalogue (`donnees/annonces/`,
`donnees/visuels/`) vivent dans un seul bucket R2. Le site lit le catalogue
par l'API S3 du bucket ; les visiteurs reçoivent les photos par le domaine
public du bucket ; l'admin envoie ses photos directement au bucket avec une
URL signée délivrée par `/api/admin/upload`.

## Mise en place (une fois)

1. **Bucket** — Cloudflare → R2 → *Create bucket*. Nom : `petita` par
   exemple. *Location* : **Specify jurisdiction → European Union**, pour que les
   données restent dans l'UE. Classe de stockage : *Standard*.

2. **Domaine public** — bucket → *Settings* → *Custom Domains* → *Add* :
   un sous-domaine d'un domaine géré par Cloudflare, par exemple
   `photos.atelierpetita.fr`. Ne pas activer l'URL `r2.dev`, limitée en débit
   et réservée au développement.

3. **CORS** — bucket → *Settings* → *CORS Policy* → coller :

   ```json
   [
     {
       "AllowedOrigins": [
         "https://atelierpetita.fr",
         "https://www.atelierpetita.fr",
         "http://localhost:3000"
       ],
       "AllowedMethods": ["PUT"],
       "AllowedHeaders": ["content-type", "cache-control"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```

   Ajouter l'adresse des préversions Vercel si l'admin y sert aussi. Sans
   cette règle, l'envoi d'une photo échoue avec « la connexion au stockage a
   échoué ».

4. **Jeton d'API** — R2 → *Manage API tokens* → *Create API token* →
   permission **Object Read & Write**, limité au seul bucket `petita`. Noter
   l'*Access Key ID* et le *Secret Access Key* (affiché une seule fois), ainsi
   que le point d'accès S3 affiché sur la même page.

5. **Variables d'environnement** (Vercel → projet → *Settings* →
   *Environment Variables*, Production et Preview, et `.env` en local) :

   | Variable | Valeur |
   |---|---|
   | `R2_ENDPOINT` | `https://<id-du-compte>.eu.r2.cloudflarestorage.com` |
   | `R2_ACCESS_KEY_ID` | Access Key ID du jeton |
   | `R2_SECRET_ACCESS_KEY` | Secret Access Key du jeton |
   | `R2_BUCKET` | `petita` |
   | `R2_PUBLIC_URL` | `https://photos.atelierpetita.fr` |

   `R2_PUBLIC_URL` et `R2_ENDPOINT` sont lus **au build** (CSP, hôtes autorisés
   par l'optimiseur d'images) : toute modification demande un redéploiement.

## Migration depuis Vercel Blob

Avec `BLOB_READ_WRITE_TOKEN` **et** les variables `R2_*` dans `.env` :

```bash
npm run migrer-vers-r2 -- --essai   # inventaire, ne copie rien
npm run migrer-vers-r2              # copie les photos et la version courante du catalogue
```

Le script peut être relancé : les photos déjà copiées sont sautées. Il réécrit
les URLs Blob du catalogue vers `R2_PUBLIC_URL` et finit en vérifiant que chaque
photo citée existe dans R2.

Ordre conseillé : ne plus rien publier dans l'admin, lancer la migration,
déployer, contrôler le site, puis seulement supprimer le store Blob et la
variable `BLOB_READ_WRITE_TOKEN`.
